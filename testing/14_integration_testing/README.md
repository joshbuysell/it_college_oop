# Звіт до роботи

## Тема: Інтеграційне тестування Flask-застосунку

### Мета роботи

Навчитися перевіряти взаємодію Flask-маршрутів, SQLite-бази даних і JSON-файлів
в одному інтеграційному сценарії без заміни цих компонентів mock-об'єктами.

### Виконання роботи

Роботу виконано за матеріалами:

- [Завдання про інтеграційне тестування](https://github.com/BobasB/it_college/tree/main/notes/07_testing/04_integration_testing)
- [Зразок оформлення звітів](https://github.com/BobasB/it_college/tree/main/reports)

Створено Flask-застосунок для роботи із завданнями. Він:

- створює таблицю `tasks` у SQLite;
- приймає завдання через `POST /tasks`;
- повертає список через `GET /tasks`;
- експортує актуальний список у JSON;
- видаляє завдання через `DELETE /tasks/<id>`.

Тести використовують `tmp_path`, тому кожен сценарій працює з окремою
тимчасовою базою та JSON-файлом. Реальні SQLite та файлова система не замінені
mock-об'єктами.

### Перевірені сценарії

- створення таблиці SQLite;
- HTTP-відповіді `200`, `201`, `400` і `404`;
- створення завдання та перевірка запису в SQLite;
- перевірка експорту створеного завдання у JSON;
- отримання порожнього списку;
- POST без поля `title`;
- створення двох завдань із перевіркою порядку;
- експорт порожньої бази;
- помилковий JSON через `JSONDecodeError`;
- видалення завдання з бази та JSON-файла.

### Команди запуску

```bash
python -m pip install flask pytest
pytest -v
pytest test_app.py::test_create_task_persists_in_database_and_json -v
```

### Результат

```text
9 passed
```

### Взаємодія компонентів

Тест створення завдання одночасно перевіряє HTTP-клієнт Flask, маршрут
`POST /tasks`, бізнес-логіку валідації, SQLite-запис і JSON-експорт. Тест
видалення проходить зворотний шлях: HTTP-запит викликає маршрут DELETE, запис
видаляється з SQLite, після чого оновлюється JSON-файл. Це відрізняє
інтеграційний тест від юніт-тесту, який перевіряє одну функцію ізольовано.

### Висновок

У роботі створено Flask-застосунок із SQLite та JSON-експортом і перевірено
повний сценарій взаємодії цих компонентів через тестовий клієнт Flask. Усі
завдання виконано, 9 тестів пройшли успішно. Отримано практичні навички
створення тимчасових ресурсів, перевірки HTTP-статусів, фактичних записів у
базі даних та результатів роботи з файлами без використання mock-об'єктів.
